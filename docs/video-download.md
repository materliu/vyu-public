# 视频下载、离线保存与导入

V语从网页中识别视频来源，下载完成后检查文件和音视频资产，再加入可播放的离线库。网页能够播放，不代表服务器允许独立下载，也不代表当前版本支持该媒体格式。

## 选择并下载视频

1. 打开网页，播放想保存的视频。
2. 点该播放器旁的“下载此视频”。App 会重新读取对应视频的当前来源，准备下载；网页保持打开。
3. 点轻提示中的“查看”，或进入“离线”，查看下载状态和失败原因。

动态加载的视频和 HTTP/HTTPS iframe 中的视频也会尝试添加入口。识别依赖页面结构和 WebKit 能提供的信息，特殊播放器可能没有独立下载入口。此时可查看底部“视频来源”，手动选择并检查候选；候选数可能包含同一视频的多个画质和旧链接。

重复点击正在准备、下载或已有完整本机文件的视频不会重复创建任务。符合继续条件的暂停任务会沿用原记录恢复。

### 视频标题

标题优先采用播放器明确声明的名称或关联标签，其次读取同一视频卡片内的局部标题和短文本；找不到可靠标题时回退到页面标题。识别会避开作者、时间、标签、操作按钮和相邻卡片，并限制扫描范围。

点击下载时会重新获取标题。选中的标题用于下载确认、任务记录和离线列表，同一视频的已确认 MP4 备选也沿用该标题。网页布局没有可靠关联时，仍可能显示页面标题。

## 支持范围

| 来源 | 当前行为 |
| --- | --- |
| 可直接访问的完整视频文件 | 下载后检查可播放性、时长和音视频轨；符合条件的普通文件可使用系统后台下载。 |
| 需要 Cookie 的普通视频文件 | 仅在有效会话范围内使用匹配的 Cookie；请保持 App 在前台，登录失效后需回到网页重新登录。 |
| 完整、未加密的 HLS 点播 | 支持部分格式；可处理的 fMP4 优先生成普通 MP4，其他适用格式使用系统离线资产。 |
| 需要 Cookie 的 HLS | 当前不支持离线保存，仍可在网页播放和收藏。 |
| 直播、DASH 离线封装、DRM 或加密内容 | 当前不支持，不绕过站点访问控制。 |
| `blob:`、MSE 播放器 | 只能尝试识别其真实媒体来源；临时地址、初始化文件和单个分片不能作为完整视频保存。 |

当前 App 的正常 HLS 下载均需要保持前台。切到后台会暂停，回到 App 后点继续会重新下载；不承诺 HLS 后台续传。系统对普通文件的后台调度也可能受网络变化、系统回收和用户结束 App 影响。

## 进度与批量操作

离线列表显示标题、来源、预览图和下载状态。传输时显示实际收到的字节数；总大小未知时明确注明。只有已知总大小或系统提供可靠比例时才显示百分比，不能用清单大小估算完整视频大小。

传输结束后会显示“下载结束，正在检查视频”。进度到达末尾不代表已经通过校验，网页、登录页、截断文件和无法播放的媒体不会标记完成。

- “全部继续”作用于所有符合恢复条件的本机下载，不受当前搜索或收藏筛选影响。
- “选择”模式可逐项勾选；“全选当前筛选”只选择当前筛选中的本机条目。云端视频不参与批量操作。
- “继续所选”和“暂停所选”只操作当前具备对应能力的任务。已完成、失败和取消的任务不会被批量继续重新下载。
- 过滤或删除条目会收敛选择；退出选择模式或离开离线页会清空勾选。选择模式中的视频行不会触发播放和单项菜单。
- 批量恢复使用有限并发，其余任务等待；暂停等待中的任务可撤销恢复请求。授权失效的条目会说明原因。

App 在前台且有实际下载工作时临时保持屏幕常亮，任务结束、暂停或 App 离开活动状态后恢复系统设置。这不会阻止手动锁屏，也不能保证后台下载持续运行。

## HLS 检查与保存

### 清单、画质与音轨

预检查区分主清单、画质清单和音轨清单，并保留服务器实际返回的 HTTP 状态。每个画质检查自己引用的音轨组，共用音轨清单复用检查结果。

部分分支失败时，只提供已通过检查、可独立保存且不依赖外部音轨的完整点播叶清单。需要独立音轨时，不能把无声视频轨当作完整内容保存；没有满足条件的分支时显示失败原因。

初始化文件可能也使用 `.mp4` 后缀。App 会利用页面已收到的清单引用排除已确认的初始化文件和分片，而不是仅凭后缀判断。WebKit 内部响应不一定对脚本可见，因此仍需下载前检查和完成后验证。

### 请求与文件校验

HLS 预检查和后续传输需要采用一致的正常请求上下文。网页准备的 HLS 会在前台传输清单、初始化段、媒体分片和音轨，按页面请求策略处理 User-Agent、Origin 和 Referer。重定向后的相对引用基于有效地址解析，不猜测或改写资源签名。

支持的 fMP4 点播通过 AVFoundation 生成普通 MP4。其他适用格式可通过本机受限传输入口交给系统保存 `.movpkg` 离线资产；入口只供本 App 的已登记资源使用。两条路径都限制资源读取，并在完成后检查媒体。

MP4 导出会核对清单时长、实际媒体样本覆盖和输出音视频轨。校验考虑媒体时间映射及可变、低帧率素材，不单凭容器报告的时长或进度判断完整性。格式不支持、样本缺失或导出不完整时不会标记完成。

系统离线资产保留 AVFoundation 返回的位置，不按解析后的路径重建播放地址。本机 bookmark 可辅助恢复失效的地址，恢复后仍检查容器范围、文件存在性和可播放性。

### 已有 HLS 离线包

`.movpkg` 系统离线包不直接进入 iCloud 文件同步。iCloud 可用时，App 可重新请求其原始来源并尝试生成 MP4；也可从视频菜单选择“准备 iCloud 同步”重试。

只有新 MP4 通过验证并成功保存状态后，才替换原记录并进入同步。来源过期、格式不支持、取消或准备失败时保留原视频，不会自动反复重试。已有包能离线播放，不代表原链接仍可重新获取；必要时回到网页重新选择来源。

## 同一视频的 MP4 备选

只有页面明确提供同一视频的 MP4 来源时，才显示备选。关联来自同一个播放器的来源列表，或页面自身已收到的同一媒体变体数据；同时校验所属 frame 和本次页面导航。App 不通过猜测地址、替换后缀或使用相邻视频来生成备选。

下载失败后，可在适用的“处理”入口中选择“检查 MP4 版本”，也可从“视频来源”查看。发现备选不会自动开始下载，MP4 地址仍须单独通过检查，不能保证换格式即可解决 HTTP 403。

## 授权与 HTTP 错误

下载准备会读取视频所属 frame 的正常请求上下文，包括 User-Agent、Referrer-Policy 和匹配视频的 crossorigin。页面或 frame 已变化时拒绝沿用旧候选。Cookie 按请求模式和作用域筛选，重定向后重新检查域、路径、过期时间和 HTTPS 条件，不扩展网页原有权限。

普通文件的 HEAD 检查被拒绝或返回网页时，可尝试受限 GET 探测，收到响应头后取消；不会为获取文件大小读取整个视频。

普通文件遇到适用的 HTTP 401/403 时，可通过“用网页会话重试”使用同一个 WKWebView 的公开 WKDownload 接口。此通道只支持前台传输和取消，暂不支持暂停、重启后续传或后台保证，也不适用于 HLS 或 DASH。

HTTP 401、403、410 会按实际状态报告。错误可能来自主清单、某个画质或音轨请求，也可能发生在实际文件传输阶段；不能只凭状态码确定链接过期。可先在网页重新播放，再点对应视频旁的下载入口；服务器仍拒绝时，不绕过访问限制。

## 录屏或本地视频导入

离线页提供“导入录屏/视频”。可先使用系统录屏，在相册裁剪，再通过系统选择器选择、预览并导入。App 只读取用户选中的视频，不需要访问整个相册。

导入的 MP4、MOV、M4V 通过媒体检查后进入离线库，支持预览图、播放和合格文件的 iCloud 同步。录屏是否允许、是否有声音由系统及内容提供方决定；黑屏或缺失声音不能通过导入恢复。取消或失败会清理临时副本。

## 本机数据与云同步

下载来源、请求上下文、Cookie、恢复数据和系统资产定位信息保留在本机，不进入应用的 iCloud 文档同步。本机诊断只记录受限的阶段、媒体类型、检查结果和允许的数字错误码，不记录网址、标题、请求头或 Cookie。

经验证的 MP4、MOV、M4V 可自动进入 iCloud 同步，包括支持的 HLS 导出结果和本机导入视频。同步条件、上传内容及删除行为见 [iCloud 同步](icloud-sync.md)。开发用 LocalOnly 配置与正常同步构建的区别见 [README](../README.md)。

## 验证边界

受控测试可以检查来源关联、请求策略、状态恢复和文件完整性，不能证明所有站点都可下载。真实站点会变化，网页登录状态也可能只适用于某条播放链路。不同 iOS 版本、设备、网络和 iCloud 多设备场景仍需分别验证。

问题报告请优先使用合成页面或可公开的最小示例，提供复现步骤与界面错误；不要提交私人页面、原始媒体签名地址、Cookie 或个人视频。
